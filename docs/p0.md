# P0 设计：统一 AgentIR 命名与编译入口 + 修正 Until 语义

> 目标：消除三处同名冲突（AgentIR/AgentProgram/compile），让连接图模型成为唯一
> canonical IR；按 DRAFT §12.1 修正 Until 协商语义，把 text/thinking 从死路径救活。
> 本设计沿用 dsh connection 的流程：主 agent 设计 → 思考 agent 预判/评审 → 实现 subagent 落地。

## 1. 现状与问题

### 1.1 三处同名冲突（代码事实）

| 名字 | packages/core（连接内核，@effect-agent/core） | src（业务模型层） |
|---|---|---|
| AgentIR | { version?, input, output, connections[], entry, metadata? } 连接图；compile → { ir, run }，run = runtime.invoke(entry...) | { id, output: OutputSpec, behavior, connections?, resources?, metadata? } behavior 驱动；compileAgent → typed AgentProgram |
| AgentProgram | { ir, run }（无类型参数） | AgentProgram<I,O,E,R>（typed，capabilities + run） |
| compile | compile(ir, runtime) 图编译 | compileAgent(ir, env) behavior 编译 |

引用面（已 grep 实测）：src/ir.ts 自用 7 处；test/ir.test.ts 从 ../src/ir.js 导入
BehaviorRegistry/compileAgent/parseAgent；core-kernel.test.ts 与 dsh-sdk-adapter.test.ts 从
@effect-agent/core 导入 canonical AgentIR。影响面小且边界清晰。

### 1.2 Until 协商现状（实测矩阵，当前代码）

             text      thinking  toolCall  stop  schema
vercel       REJECT    REJECT    REJECT    OK    OK
claude-code  REJECT    REJECT    REJECT    OK    OK
codex        REJECT    REJECT    REJECT    OK    OK
pi           REJECT    REJECT    REJECT    OK    OK

根因：requireUntil 的 Text 分支无条件要求 pause:true（比 DRAFT §12.1 严格），
Thinking 要求 thinking && pause，ToolCall 要求 toolCalls === "intercept"；
而 4 个 driver 全部 pause:false、toolCalls: "observe"。

## 2. P0(a) 决策：AgentIR 唯一化（命名统一，不做深层合并）

1. canonical AgentIR = packages/core 的连接图模型：可序列化、浏览器安全、已被
   core-kernel.test.ts 与 dsh adapter 集成测试覆盖；DRAFT §28 最终命题（Connection 注册
   远程资源，URI 统一标识和解析整个 Agent 世界）以连接图为终态。
2. src/ir.ts 的 AgentIR 更名为 BehaviorSpec：它是带 LLM 行为的声明式 Agent，
   编译产物是业务层 typed AgentProgram，内部可经 Connections 使用连接内核。
   - parseAgent → parseBehaviorSpec（JSON/YAML/TOML 入口不变）
   - compileAgent → compileBehavior（BehaviorRegistry 语义不变）
3. 编译入口统一：AgentIR + compile（图）只从 @effect-agent/core 导出；
   src/index.ts 不再导出任何名为 AgentIR 的类型。
4. packages/core 的 AgentIR 增加可选 id?: string（与 BehaviorSpec 对齐，便于日志/错误归因），
   不改其他语义。
5. **第二处同名一并消解**：packages/core 的 AgentProgram（{ ir, run }，无类型参数）更名为
   GraphProgram —— 与 src 的 typed AgentProgram<I,O,E,R> 彻底区分。引用面（grep 实测）：
   两个测试文件只 import AgentIR 类型，未按名引用 core 的 AgentProgram，仅 core 自身导出受影响。
6. 关系文档化：BehaviorSpec 是高层声明，未来可 lowering 为连接图（P2 再做真正合并）；
   本阶段只消除同名歧义与双入口，不做深层类型合并。

文件级改动：
- packages/core/src/agent.ts：AgentIR + id?: string；AgentProgram→GraphProgram（含导出）
- src/ir.ts：AgentIR→BehaviorSpec、parseAgent→parseBehaviorSpec、compileAgent→compileBehavior、
  compileAgentProvided→compileBehaviorProvided（BehaviorExtension.create 签名同步改名）
- src/index.ts：确认 ir.js 不再导出 AgentIR（无冲突即不动）
- test/ir.test.ts：适配新名
- docs/p0.md（本文档）＋ IMPLEMENTATION.md 增补 IR 分层小节

## 3. P0(b) 决策：Until 语义按 DRAFT §12.1 修正

1. requireUntil 的 Text 分支去掉无条件 pause 要求：§12.1 语义是返回下一段 Text，
   仅当需要命中后立即暂停才要求 pause。观察级（run 完成返回最终文本）是所有 driver 的基本
   能力，分支均已实现（vercel result.text / claude-code result.result / codex finalResponse /
   pi textOf）。
2. Thinking 分支只要求 capabilities.thinking（去掉 pause）。vercel/claude-code/pi 已实现
   thinking 分支 → 可用；codex 改 thinking: false（诚实化：SDK granularity=turn、无 token
   delta，driver 无 thinking 分支，声明 thinking:true 是虚标——修正它而不是假装能返回）。
3. ToolCall 保持 intercept 要求不变：observe 模式的 toolCall 是工具已执行后报告调用，
   与 Until.toolCall 的暂停语义不符；IMPLEMENTATION.md 明确不假装暂停，统一事件/暂停协议
   （P1 线）完成前保持 REJECT。
4. 新增 test/capability-matrix.test.ts 固化协商矩阵（5 Until × 4 Driver），防回归
   （此前矩阵是我手工验证的，现在写成测试）。

预期矩阵（P0(b) 后）：

             text      thinking  toolCall  stop  schema
vercel       OK        OK        REJECT    OK    OK
claude-code  OK        OK        REJECT    OK    OK
codex        OK        REJECT    REJECT    OK    OK
pi           OK        OK        REJECT    OK    OK

文件级改动：
- src/core.ts：requireUntil Text/Thinking 分支
- src/composed/codex.ts：thinking: false
- test/capability-matrix.test.ts：新增（5×4 矩阵断言）
- src/ir.ts：untilOf 无需改（text/thinking 现在可达），但确认 OutputSpec 的 text/thinking
  kind 在矩阵测试中可达

## 4. 验收标准

1. bun run typecheck + bun test 全绿（含适配后的 ir.test.ts、新增矩阵测试）；
2. grep -rn "AgentIR" src/ 无 src 本地定义（只剩 @effect-agent/core 引用）；
   且 grep -rn "AgentProgram" src/ 只剩 src 的 typed 版本（core 的 GraphProgram 无泄漏）——
   三处同名全部消解，验收不遗漏；
3. 矩阵测试断言：text 全 OK；thinking vercel/cc/pi OK、codex REJECT；toolCall 全 REJECT；
   stop/schema 全 OK；
4. packages/core 语义零改动，导出面变化仅两项（AgentIR + id?: string、AgentProgram→GraphProgram）；
   src 业务 API 除重命名与 until 放宽外零行为回归；
5. 交付说明按上述文件清单 + 自测结果 + 偏差说明。

矩阵测试机制（诚实性约定）：矩阵测试**只测协商路径，不触发真实 LLM 调用**——对每个
driver 的声明 capabilities 逐项调 requireUntil 断言 outcome（UnsupportedCapability 或 void），
mock 掉底层 SDK client。若某 driver 的 capabilities 声明与 run 实际行为不一致，由实现 agent
在该测试中显式标注并在交付说明中报告（防"声明通过但运行失效"的假绿）。

## 5.5 评审待补条件（并入实现范围，全部低风险）

1. **vercel Thinking 分支 "?? " 归一**：src/vercel.ts 的 Thinking 分支改
   reasoningText ?? ""（无 reasoning 模型下返回 undefined 是运行时类型谎言；cc/pi 已归一）。
2. **core AgentIR 的 +id 用起来**：compile 的校验错误（entry 未声明/能力未要求/连接缺失）与
   InvalidAgentIR 带上 ir.id（动机是日志/错误归因，不留半截字段）。
3. **test/ir.test.ts 的 describe 字符串** "declarative AgentIR" -> "declarative BehaviorSpec"
   （repo 级 grep 不残留 AgentIR 字符串）。
4. **claude-code 的 ToolCall 分支加注释** "P1 事件/暂停协议后启用"（保留分支，不删除；
   不得顺手标成可用——与 ToolCall 保持 REJECT 矛盾）。
5. **IMPLEMENTATION.md 同步**：adapter 状态表 codex 行补 "thinking 未接（SDK 仅 turn 粒度）"；
   协商矩阵段落更新为 P0(b) 后形态（text/thinking 放宽），与矩阵测试结论一致。

## 5.6 开放问题决策（主 agent 已定）

1. **codex reasoning-summary 提取 -> P1 候选**：thinking:false 是正确收缩（SDK 无完整思维链），
   但 Codex SDK 基于 Responses API，理论上可提取 reasoning items（summary 级）。
   P1 候选 + IMPLEMENTATION.md 记录，避免"收缩即终态"误读。
2. **"canonical"措辞**：表述为"命名与编译入口的 canonical，语义合并 P2"——
   P0(b) 证明 Until 语义只在 src 层（core AgentIR 无 Until 概念），避免文档与代码分层矛盾。

## 5. 风险与开放问题

- codex thinking:false 是能力面收缩（行为变化）：接受，诚实优先（§3.5 不伪造能力）；
- Until.text 观察级语义：run-until-complete 模式下返回最终文本而非第一段文本，
  与 §12.1 在完整 run 下等价，文档注明；实现时在 untilOf 注释标注 text/stop 在此模式下的
  别名关系（text 观察级 = stop 的最终文本），防止使用者误以为 text 会暂停；
- BehaviorSpec lowering 到连接图留 P2（本期不做深层合并）；
- 与 dsh adapter（已完成）无冲突：adapter 在 connection 层，不受命名影响；
- 若 src/index.ts 或 examples 有对旧名的引用（grep 未发现），实现时逐个更新并在报告中列出。
